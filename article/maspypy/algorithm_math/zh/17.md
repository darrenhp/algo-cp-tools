### 概要

前回 → Segment Tree 的学习 (1) 为前提。

能进行 1 点更新、区间作用、区间积获取的 Segment Tree。

所谓非递归实现

1-based index

不假设 $N=2^n$

 monoid $A$ 右作用于 monoid $X$。各自 monoid 的二元运算用积形写为 $$\begin{align*}A\times A\longrightarrow A;\quad (a,b)\mapsto ab,\\X\times X\longrightarrow X;\quad (x,y)\mapsto xy\end{align*}$$。作用写为 $$X\times A\longrightarrow X;\quad (x,a)\mapsto x^a$$ 的指数形。

 monoid：满足结合律 $(xy)z = x(yz), (ab)c = a(bc)$（也有单位元）。

右作用：满足 $(xy)^a=x^ay^a$, $x^{ab} = (x^a)^b$（另外假设单位元的作用是平凡的等）。

本文不处理 monoid、作用的具体例。左作用（$(ab)x = a(bx)$）也行，那个看喜好。是时系列顺序中后做的作用想用 $A$ 的运算挂在左右哪边。

写 $x_i$ 等则是 monoid $X$ 的元素。$a,b,c$ 等是 $A$ 的元素。给定 $X$ 的元素列 $[x_0,x_1,\ldots,x_{N-1}]$ 时，处理

- 改变 $x_i$ 的值
- 把 $x_L,\ldots,x_{R-1}$ 同时改为 $x_i^{a}$
- 计算 $\prod_{L\leq i < R} x_i$

的 Segment Tree。利用 $x_1^ax_2^ax_3^ax_4^a = (x_1x_2x_3x_4)^a$ 等成立，把对区间积的作用汇总计算，从而实现每查询 $O(\log N)$ 次运算（monoid 的运算或作用）。

作用也有依赖于元素数或两端下标者，但那种也能在此框架下处理。例如取 monoid $X$ 时，令 $Y = \N\times\N\times X$，把 $y_1=(L_1,R_1,x_1)$ 与 $y_2=(L_2,R_2,x_2)$ 的积定义为 $(L_1,R_2,x_1x_2)$ 的 monoid $X$（适当加单位元），就能把两端下标包含进作用的定义。当 $R_1 = L_2$ 不成立时虽应视为未定义、或视为处理的是范畴而非 monoid，但不管它继续。

边观察实现，特别是具体值上仔细可视化算法，目标是获得能立刻从 $0$ 实现的老练理解。

### 可视化

我的实现例：https://yukicoder.me/submissions/470340

首先以 $N = 8$ 来做。在放代码前，先一味地可视化“做什么会怎样”吧（这点尤其非交换时不够充实，很困扰）。

#### 区间作用

省略作用元的单位元。把目标区间分割为 $O(\log N)$ 个区间，在那里追加作用元。这立刻能想象。此外还需前处理与后处理，需要如下 $3$ 步：

- （１）作用元的传播
- （２）作用元的追加
- （３）再计算

实际行为的图示，我个人觉得很有助于理解。其实只看这个就感觉能自己实现。

单元格的数据 $(x,a)$ 大致意味着对应区间积为 $x$、且作用元 $a$ 正作用着。不过，要包含该单元格上方的所有作用元一起评价，才能第一次得到正确值。可观察到越上段作用元的反映越完成，越下段作用元的反映越延迟。为何越上方越优先反映完？因为有如下区别：

- 某单元格从其正上方全部拿到信息很简单（$O(\log N)$ 个）
- 某单元格从其正下方全部拿到信息很难（$O(N)$ 个）

下段单元格没能持有最新作用元，但需要时能立刻从上方拿到。另一方面，若需要时才慌忙去拿下方信息，不知所需者在哪，所以更新某单元格时必须那一瞬把计算反映到上部（步骤（３））。

步骤（１）在作用元可交换时不需要。作用非交换时，须注意别让作用顺序迷路。因此，先把要追加作用的区间上部改写为没有作用元残留的状态，再追加作用元。保持“上方的”作用元比“下方的”作用元在时系列顺序上后追加的状态。

实现确认留后，区间积的计算、1 点更新的计算也先可视化。

#### 区间积

该做的很简单。对参照的区间，传播来上方的作用元。其余与普通（无延迟传播的）Segment Tree 相同。上例计算积 $x_8^ax_9^{ac}x_{10}^{abc}x_{11}^{abc}x_{12}^{abc}$。

#### 1 点更新

只要把含目标点的区间里残留的作用元传播掉，其余只需从下段更新上去。（１）中传播时计算了 $x_{10}^{abc}x_{11}^{abc}$ 部分，但这里反正会被重算，所以也能省略（实现仅稍增）。

#### 取得要传播的下标

区间作用 （１）（３）

区间积 （１）

各自需要对目标单元格正上方的单元格群做作用元传播或再计算。只要知道那群单元格到底是什么，实现的难点就结束了。

以 $N=40$, $L=45$, $R=78$ 可视化一下。

作用元与积的计算对象是粉色单元格，传播或再计算的是黄色单元格。

因非 $N=2^n$ 的图，例常一部分会进异常值。

排列在计算对象区间正上方的区间。其实只需看“左端、右端的计算对象区间”的正上方就够了。上图情形即 $45$ 号、$38$ 号单元格的正上方。

因此，只要能取得两端的计算对象区间即可。回想 Segment Tree 的区间积计算。只看下标迁移，是这样的感觉：

```
while L < R:
    if L & 1:
        (乘上单元格 L 的值)
        L += 1
    if R & 1:
        R -= 1
        (乘上单元格 R 的值)
    L >>= 1
    R >>= 1
```

特别地，确认到初次成为计算对象之前的迁移极简单。$L$, $R$ 都是一直除以 $2$ 直到变奇数。

因此，对区间 $[L,R)$ 作用 $a$ 时，例如如下即可：

```
L0 = L // (L & -L)  # L 除以 2 直到变奇数
R0 = R // (R & -R)  # R 除以 2 直到变奇数
(传播 L0 的正上方)
(传播 R0 的正上方)
while L < R:
    if L & 1:
        (对 L 追加作用元 a)
        L += 1
    if R & 1:
        R -= 1
        (对 R 追加作用元 a)
    L >>= 1
    R >>= 1
(再计算 L0 的正上方)
(再计算 R0 的正上方)
```

对某单元格的正上方，注意传播：从上到下顺序、再计算：从下到上顺序，实现即完成。再计算就是平时的。

```
while i > 1:
    i >>= 1
    (用 2i, 2i+1 的值计算 i 的值)
```

传播从上到下顺序进行。注意 $i$ 上方第 $n$ 个单元格是 $\lfloor\frac{i}{2^n}\rfloor$，这也只是简单循环：

```
h = (使 2^h <= i 成立的最大 h)
for n in range(h, 0, -1):
    (在 i >> n 处传播)
```
