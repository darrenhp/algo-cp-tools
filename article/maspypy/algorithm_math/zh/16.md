## FFT 与卷积（フーリエ変換と畳み込み / FFT による畳み込み）

### 概要

在“用 Python 做竞技编程”的语境下，整理使用快速傅里叶变换的基础知识。

快速傅里叶变换本身在竞技编程之外也是重要的算法，但本文不打算应对那种需求。

本文不触及快速傅里叶变换的详细算法（已有大量解说）。作为替代，稍微整理了一下关于傅里叶变换的基础知识。这里是与使用语言无关的部分。

只想看 Python 实现的人，大部分可以跳过。

### 傅里叶变换的性质

#### 傅里叶变换的定义

详细内容本文不处理。

设 $K$ 为持有 $n$ 个 $1$ 的 $n$ 次根的域（竞技编程语境下 $K=\C$ 与 $K=\F_p$ 重要）。

对取值于 $K$ 的数列 $A = (a_0,a_1,\ldots,a_{n-1})$，定义其傅里叶变换 $\mathcal{F}_n(A) = (\hat{a}_0,\ldots,\hat{a}_{n-1})$。也有逆变换 $\mathcal{F}_n^{-1}$。这些映射 $\mathcal{F}_n, \mathcal{F}_n^{-1}$ 依赖于 $n$。

※ 一般化而言：

- 对有限 Abel 群 $G$ 与其对偶模 $\hat{G}$，定义 $\mathcal{F}_G\colon K[G]\longrightarrow K[\hat{G}]$
- 本文说明的是 $G = \Z/n\Z$ 的情形
- 竞技编程中 $G=(\Z/2\Z)^n$ 的情形也有名（阿达马变换）
- 含非 Abel 群的一般化，有由不可约表示作群环分解。有兴趣者请沿“有限群表示论”关键词学习。

#### 与卷积的关系

数列 $A = (a_0,\ldots,a_{n-1})$ 与 $B = (b_0,\ldots,b_{n-1})$ 的卷积 $C = (c_0,\ldots, c_{n-1})$ 由 $c_k = \sum_{i+j\equiv k\pmod{n}} a_ib_j$ 定义（即群 $\Z/n\Z$ 上的卷积，也称周期 $n$ 的循环卷积）。此时成立：

**【定理】（卷积定理）** $\mathcal{F}_n(C)$ 与 $\mathcal{F}_n(A)$ 和 $\mathcal{F}_n(B)$ 的点积一致：$\hat{c}_i = \hat{a}_i\cdot \hat{b}_i$。因此可由 $C = \mathcal{F}_n^{-1}(\mathcal{F}_n(A)\cdot \mathcal{F}_n(B))$ 计算卷积。

特别地，设对长度 $n$ 数列做傅里叶变换/逆变换的复杂度为 $F(n)$，则卷积可在复杂度 $3F(n) + \Theta(n)$ 下计算（基于定义的单纯算法复杂度为 $\Theta(n^2)$ 时间）。

### 快速傅里叶变换

本文不触及算法，但请一定学一学。

**【定理】（快速傅里叶变换）** 当 $n = \prod p_i$ 分解为自然数之积时，$\mathcal{F}_n$, $\mathcal{F}_n^{-1}$ 可在复杂度 $\Theta(n\sum p_i)$ 下计算。特别地取 $n = 2^k$ 时，复杂度为 $\Theta(n\cdot 2k) = \Theta(n\log n)$。

因此得到：

**【定理】（快速傅里叶变换的循环卷积）** 当 $n = \prod p_i$ 时，数列 $A = (a_0,\ldots,a_{n-1})$ 与 $B = (b_0,\ldots,b_{n-1})$ 的卷积 $C = (c_0,\ldots,c_{n-1})$ 可在复杂度 $\Theta(n\sum p_i)$ 下计算。

傅里叶变换本身对任意 $n$ 都能定义与计算。基于定义的单纯方法复杂度为 $\Theta(n^2)$，但当能分解为小质因数时复杂度大幅改善，那种情形就称为快速傅里叶变换。

从群表示的视角看，是利用子群塔 $\Z/n\Z=G_0\supset G_1\supset G_2\supset \cdots \supset G_k=0$ 与诱导表示来分解傅里叶变换（也可一般化到非 Abel 群）。

### 通常加法下的卷积（多项式之积）

上述卷积是 $\Z/n\Z$ 上加法相关者 $c_k = \sum_{i+j\equiv k\pmod{n}}a_ib_j$。想计算不取 $\pmod{n}$ 的情形，例如多项式之积即属此类。

对 $A=(a_0,a_1,\ldots)$ 与 $B = (b_0,b_1,\ldots)$，由 $c_k = \sum_{i+j=k}a_ib_j$ 定义 $C = (c_0,c_1,\ldots)$。进一步设

- $i\geq n_A \implies a_i = 0$
- $i\geq n_B \implies b_i = 0$

成立。令 $n_C = n_A + n_B-1$，则知 $i\geq n_C\implies c_i = 0$。

于是取 $n \geq n_C$，做 $\Z/n\Z$ 上的卷积（周期 $n$ 的循环卷积）。要点是：对 $i,j,k< n_C$ 有 $i+j\equiv k\pmod{n}\iff i+j=k$，故若记 $\Z/n\Z$ 上卷积计算结果为 $D = (d_0,d_1,\ldots,d_{n-1})$，则对任意 $i < n_C$ 有 $c_i = d_i$。

因此利用循环卷积，也能计算通常加法下的卷积。这是“把 $\Z$ 嵌入 $\Z/n\Z$！？”这一有趣想法。

特别地，选 $n$ 为不小于 $n_A+n_B-1$ 的最小 $2$ 次幂，得到：

**【定理】（快速傅里叶变换的卷积）** 有数列 $A = (a_0,a_1,\ldots)$ 与 $B = (b_0,b_1,\ldots)$，且成立 $i\geq n_A \implies a_i = 0$, $i\geq n_B\implies b_i = 0$。它们的卷积 $C = (c_0,c_1,\ldots)$（$c_k=\sum_{i+j=k}a_ib_j$）可在复杂度 $\Theta((n_A+n_B)\log(n_A+n_B))$ 下计算。

完全相同，也用多项式形表述一下：

**【定理】（快速傅里叶变换的卷积）** 多项式 $A, B$ 之积可在复杂度 $\Theta((\deg(A)+\deg(B))\log(\deg(A)+\deg(B)))$ 下计算。

题外话，竞技编程语境下，有时把上述步骤整体的“卷积计算”称为“快速傅里叶变换”的文献也偶见。正确的理解应是：快速傅里叶变换是卷积所用到的子算法。

### numpy.fft 的使用

#### 基本实现

基本的事还是好好读官方文档为好。

Discrete Fourier Transform (numpy.fft) — NumPy v1.19 Manual（numpy.org）

姑且做个简单实现。

FFT 中，除变换前数列外，还要指定在哪个周期（哪个 $\Z/n\Z$）变换。什么都不指定时，按与输入长度相同的周期做傅里叶变换。另外，虽称“快速”傅里叶变换，长度马虎的话也不快。这里以 $2$ 次幂长度实现。

细节：输入仅有实数时，与 numpy.fft.fft 相比，numpy.fft.rfft 性能稍好。

#### 与 numpy.convolve 的比较

numpy 也有卷积用的函数 numpy.convolve。它的复杂度是 $\Theta(N^2)$。

长度约 1000 起，基于 FFT 的方法更快。

#### $n$ 的选择

fft 所用的长度不一定要是 $2$ 次幂。下一个 $2$ 次幂很远时，选能分解为小素数的适当长度也可能性能更好。

### mod p 下的计算

设 $f,g$ 为 $n$ 次多项式，想计算积 $h = fg$。特别地，在竞技编程语境中常见要求 $\pmod{p}$ 下计算。$p$ 一般为 $10^9+7$ 或 $998244353$。

此时计算误差成为问题。当 $|f_i| < p$, $|g_j| < p$ 时 $|h_i| < np^2$，但 $n=10^5$ 且 $p=10^9+7$ 时 $np^2$ 约达 $10^{23}$，远超 64bit 浮点数能正确计算的范围。

因此可用把上下各 $15$ bit 分开的技巧。

令 $f = 2^{15}f_1 + f_2$, $g = 2^{15}g_1 + g_2$，变形为 $fg = 2^{30}f_1g_1 + 2^{15}(f_1g_2+f_2g_1) + f_2g_2$。系数小的多项式之积，能用 64bit 浮点数的有效数字正确计算，把它们合起来回到 $fg$ 的计算。除卷积（多项式之积）外，也作为矩阵之积中轻松回避溢出的技巧可用。

$f_1g_2+f_2g_1$ 通常想来需 $2$ 次卷积，但用巧妙方法省了 $1$ 次。这与 Karatsuba 法做同一件事。

这样，应能应对竞技编程中要求 FFT 的大部分情形。

另外，FFT+$\bmod p$ 计算需 $3$ 次卷积，但对可取 $1$ 的 $n$ 次根的 $p$，在域 $\F_p$ 上应用 FFT（也称 NTT）的情形更快。以此为正解的问题大多是 $p=998244353$。numpy.fft 没有这个，所以要么接受慢 $3$ 倍，要么自己学 NTT 实现。
